# 任务安排规划 Skill

## 前置要求

用户至少提供：
- 项目名
- 领导/相关人安排的原话或任务描述

若缺失，先问 1-2 个问题补齐。

## 工作流程

1. 按 `project-context-maintainer` 的规则读取/维护项目上下文、内部术语表、项目工作记录。
2. 判断这是独立任务，还是大项目下的小需求点。
3. 提取任务画像：
   - 谁安排的
   - 要解决什么问题
   - 期望交付物
   - 截止时间/同步节点
   - 相关人
   - 已知约束
   - 不清楚但会影响推进的问题
4. 给出“还需要用户提供什么信息”清单，只列真正影响推进的信息。
5. 给出工作节奏：
   - 今天/下一步先做什么
   - 要找谁确认什么
   - 先产出哪个低成本版本
   - 什么时候同步
   - 哪些风险需要提前暴露
6. 如用户要落盘，写入：
   - 独立项目：`{项目目录}/任务安排/{YYYY-MM-DD}-{任务名}.md`
   - 小需求点：`{项目目录}/需求点/{需求点名称}/任务安排/{YYYY-MM-DD}-{任务名}.md`
   - **同时将"下一步行动"中的可执行项写入 `{项目目录}/任务.md`**（格式见下方任务格式规范）
7. 回写项目上下文和项目工作记录。

### 写入 任务.md 规则

1. 读取已有 `{项目目录}/任务.md`（如存在），否则创建
2. 检查是否有重复任务（通过描述关键词匹配），避免重复添加
3. 在文件中追加新段落，按来源分组：
   ```
   ## 任务安排 — {YYYY-MM-DD} {任务名}

   - [ ] {行动描述} 📅 {截止日期} {优先级} @{负责人}
   ```
4. 截止日期推断：P0 → 📅 +2天，P1 → 📅 +5天，P2 → 📅 +10天，无法判断则不加
5. 优先级映射：P0 → `🔼`，P2 → `🔻`，P1 → 不加

## 判断原则

- 先帮用户降低不确定性，再安排执行。
- 不追问所有缺口，只追问会影响方向、范围、截止时间、交付物的问题。
- 给用户可直接发送给领导/同事的话术。
- 把“待确认”和“建议先按此推进”分开。

## 输出格式

使用 `templates/task-arrangement.md`。
